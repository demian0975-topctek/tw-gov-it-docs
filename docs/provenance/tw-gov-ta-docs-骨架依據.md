# 工作說明書骨架.md 各節的來源

管轄 `skills/tw-gov-ta-docs/assets/工作說明書骨架.md`。記錄哪一節出自哪裡、章節分層動過哪些地方，
**供維護者判斷改動時會不會偏離來源案件**；skill 的使用者只需要知道「條文取自真實結案案例、分層另行
調整過」，那兩句留在骨架開頭。

兩個來源：

- **A｜來源案件**——實際結案的工作說明書 Word 檔。真實案件，**不在本倉庫**，執行者自備。
  以下條數與層級均以 `python-docx` 讀該檔的標題階層（標題1／標題2／Heading 3～5）實際比對。
- **C｜本倉庫的判斷**——重新分層、收斂、以及顧問端自己要求的交接標記，見下三節。

**不再有第三個來源。** 2026-09-01 前，封面欄位與壹章數個節次抄自機關端公版
`skills/tw-gov-it-docs/assets/13-工作說明書骨架.md`（本檔曾以 **B** 稱之）。已全數退回 A，理由見末節。

## 業務章節的收斂與下限（C）

A 把兩套業務在中控端與行動端各展開一次，共四大段。骨架收成一個 `○○○業務` 範例，讓撰寫者依實際
業務逐項另立小節。收斂讓骨架短，代價是「該寫多深」這個 A 最有價值的訊號會消失，所以下限寫成可數的，
數字取自 A 最薄的業務小節：

| 端 | A 各小節條數 | 骨架下限 |
| --- | --- | --- |
| 中控端 | 通則 5、業務甲 6、業務乙 5 | 至少 5 條 |
| 行動端 | 通則 5、業務甲 3、業務乙 5 | 至少 3 條 |

行動端原本一度訂為 4 條，但 A 最薄的小節是 3 條——訂 4 等於要求比真實發包成功的案子更嚴，而骨架
開頭宣稱條文取自 A，塞一個 A 裡不存在的門檻就是編造。骨架的行動端範例同時補到 3 條，照抄即合格。

## 為什麼顧問版沒有追溯鏈

顧問協辦的定位是幫機關把案子發出去，不是代機關做需求工程。硬塞 R-001 需求編號表會讓承辦人面對
一張填不完的空表，而 A 這份發包成功的案件也沒有這套。

配套已做：`skills/tw-gov-it-review/references/01-結構與格式.md` 第九節〈追溯鏈的起點〉載明未定稿草稿
的例外，缺編號列 `[建議]` 而非 `[退件]`。少了這一句，同一個倉庫裡會出現「審查 skill 說追溯鏈斷點要
退件，撰寫 skill 產的東西沒有追溯鏈」的矛盾。該句刻意寫成**看送審件自己標示的狀態**（封面帶工作用
版本號與「機關內部工作稿」字樣），不寫「這是 tw-gov-ta-docs 的產出」——審查者手上只有一份文件，
判不出它是哪個 skill 產的，寫成後者等於要審查者猜。

## 為什麼退回 A、不再借機關端公版（2026-09-01）

原先向 `skills/tw-gov-it-docs/assets/13-工作說明書骨架.md` 借了五處：封面的承辦單位與日期欄、
壹之一的「委託機關」、壹之五的「履約地點」、壹之六「預算金額與經費來源」整節。都是 A 沒有的。

移除的理由不是那份公版不好，而是**顧問版的賣點就是「照著發包成功過的案子寫」**。骨架開頭如此宣稱，
內容裡卻混著另一份出處的欄位，等於在同一份檔案裡混用兩套依據標準，維護者日後改動時分不清哪一句
可以動。顧問協辦的另一個實務前提也指向同一結論：各機關的工作說明書版型與慣用欄位互不相同，
借一份通用公版的欄位並不會比較保險，只會多出機關沒要求、顧問也答不出來的空欄。

代價據實記錄：**「經費來源」這個欄位在骨架裡消失了**（A 只寫金額、不寫來源）。它仍留在
`skills/tw-gov-ta-docs/references/01-顧問協辦工作說明書撰寫要點.md` 第一節「訪談務必問到的六類事實」，
顧問還是會問到；只是產出的草稿不再預留這一欄，機關若要求，照該機關格式自行加。

兩個 skill 之間**沒有任何檔案層級的依賴**：scripts 各自一份、assets 與 references 各自一套，
互相提到的只有「你是顧問改用哪個 skill」的路由句。上述借用是內容層級的，現已解除。
