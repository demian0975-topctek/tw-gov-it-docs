# 顧問協辦工作說明書撰寫

本檔是**顧問公司（或系統整合商）受機關委託，協助機關撰寫工作說明書**時的撰寫要點。適用情境：機關對資訊技術不熟悉，委由顧問先行研擬草稿，機關審閱、調整後，以機關名義循正式採購程序對外招標。

立場仍是機關端——章節骨架、需求怎麼寫才判得出合格、避免綁標之虞、交付項目怎麼訂、評選項目與配分表怎麼寫，全部沿用 `references/07-機關端工作說明書.md` 與 `assets/13-工作說明書骨架.md`，本檔不重複。本檔只處理這個情境特有的一件事：**顧問手上沒有機關內部才知道的事實，卻要交出一份精確到能驗收的文件。**

> **對外發布的文件，體例不變。** 不論實際由誰執筆，發出去的工作說明書一律以機關第一人稱撰寫，不記載撰寫來源、協辦單位或顧問公司名稱——這是所有正式招標文件的既有慣例，跟 07、13 其餘骨架的寫法一致，不是本檔額外要求的。

## 一、先分出「顧問補不出來」的欄位

`assets/13` 骨架裡，下列欄位是機關專屬事實，顧問憑經驗寫得出通用寫法，但寫不出本案真正的數字與名稱——填錯比留白更糟，因為機關審閱時未必逐字核對，等公告出去才發現金額或系統名稱錯了，已經來不及改。

| 骨架章節 | 欄位 | 為什麼顧問補不出來 |
| --- | --- | --- |
| 壹、五 | 預算金額與經費來源 | 涉及機關內部預算科目與年度額度，顧問問不到就是問不到 |
| 貳、二 | 現行資訊作業環境 | 實際規格、數量、所在位置，顧問只能陪同盤點，不能用「常見規格」代填 |
| 貳、三 | 既有系統與介接對象 | 系統名稱、管理單位、介接窗口，顧問杜撰的介接方式會讓廠商投標時無所適從 |
| 貳、五 | 機關可提供之資源與配合事項 | 場地、帳號、業務單位配合時點，只有機關能承諾 |
| 肆、二 | 內部審查層級與期程 | 機關簽核要幾層、要幾天，顧問不在機關體制內，猜不出來 |
| 伍、二 | 付款辦法 | 涉及機關財務作業期程，需機關財務或會計單位確認 |

**這張表不是完整清單**，遇到骨架其他章節時用同一個判準自問：「這格填的是通用做法，還是本案專屬的事實？」是後者，就先留 `【待填：○○】`，列進第四節的待確認清單，交機關補實，不要用合理猜測填上去。

## 二、訪談：怎麼從不懂技術的機關問出真正需求

機關承辦人不熟悉資訊技術時，常見的訪談陷阱：

- **只問「要什麼系統」，不問「現在怎麼做」。** 承辦人腦中的畫面常是他看過的某個系統，直接照做會漏掉機關實際作業流程裡的例外情況。先問現況（現在用紙本、Excel 還是舊系統？卡在哪一步？），再談系統要做什麼。
- **承辦人給的是抽象語言，顧問要追問到判得出合格的地步。** 呼應 07 第三節的判準：「這句話交給兩個不認識的人，會不會做出不同的東西？」承辦人說「系統要好操作」，顧問要追問成「哪些角色、做哪些操作、操作幾步以內完成」。
- **別讓承辦人選規格或型號。** 問「你要用哪個資料庫」問不出答案，也容易問出承辦人道聽塗說的品牌；改問業務需求（要存多少筆、多少人同時用、要保留幾年），規格由顧問依需求轉換。
- **問「不做會怎樣」，分辨必要與選擇性需求。** 對應骨架參、一需求編號表的「必要／選擇性」欄——問不出「不做的後果」的需求，多半是顧問自己覺得該有，不是機關真的要。
- **問到金額、期程這類機關專屬事實時，直接問「這個數字我該問誰」**，不要在訪談現場逼機關承辦人當場答覆他答不出來的數字，回頭列進待確認清單，交機關內部確認後回覆。

## 三、避免自家慣用規格滲入文件

顧問本身通常也是資訊服務廠商，比機關自己撰寫時更容易不自覺把自家慣用的產品、架構或用語寫進工作說明書。07 第四節「避免綁標之虞」的兩個檢查方式在這個情境下更要落實：逐條硬性規格自問「不符合這條的廠商，是真的做不到本案的事嗎」；規格描述功能性效果，不描述特定產品的做法。

## 四、交付草稿給機關：版本與交接慣例

- 顧問交付的每一版草稿另外標註**工作用版本號**（例如「顧問草稿 v0.3」），並在封面或頁首註明「機關內部工作稿，非正式版」——這組標記只在顧問與機關之間的工作副本上出現，機關核定、準備對外公告的定稿要拿掉，回到本檔開頭所述的機關第一人稱體例。
- 用可編輯格式（Markdown 或可追蹤修訂的 Word 檔）交付，方便機關直接在文件上修改、留下修訂痕跡，而不是重新謄一份。
- 每次交付附一張「待確認事項清單」（格式見 `references/03-範例集.md` 第四節），列出本版所有 `【待填】` 與其對應的第一節分類，機關看得到具體要補什麼，不用逐頁自己找。

## 五、機關核定前，顧問自我檢查

| 檢查項目 | 結論 |
| --- | --- |
| 第一節列出的機關專屬欄位，全部已交機關確認或明確標示 `【待填】`，沒有顧問自行合理猜測 | |
| 待確認事項清單已附上，機關看得到還缺什麼 | |
| 工作用版本標記（草稿字樣、版本號）已從定稿移除 | |
| 定稿內文以機關第一人稱撰寫，未出現顧問公司名稱或協辦字樣 | |
| 已跑過 `assets/13` 第拾章與 `references/07` 第十一節列的一般性自我檢查 | |
